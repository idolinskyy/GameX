# Довідка для розробника / Contributors

Дякуємо за інтерес до GameX. Цей файл — як зібрати, куди класти зміни і що в проєкт **не** входить.

Користувацька документація: [README.md](README.md) і довідка в програмі (F1). Межі продукту — розділ «Чого немає і не буде» у README.

## Ліцензія змін

Код під **GNU GPL v3** (або пізнішою). Надсилаючи патч, ви погоджуєтесь, що ваші зміни ліцензуються так само. Сторонні залежності — [NOTICE](NOTICE).

## Що приймаємо / що відхиляємо

**Так:** виправлення помилок, тести ядра, UX/документація українською, продуктивність локального пошуку/запису, Harden навколо `process_vm_*` / PID+starttime, опційні залежності (Capstone, X11) без обов’язкового runtime.

**Ні (не буде в дереві):** обхід античиту, мережевий чит, приховування процесу, NOP / code inject, speedhack, будь-що для онлайн-матчів чи чужих сервісів. Див. README.

## Архітектура

```text
gamex_core          # без Qt: пам'ять, сканер, таблиця, freeze, watchpoint…
gamex               # Qt Widgets UI + ScanWorker
gamex_core_tests    # тести ядра (без GUI)
```

| Каталог      | Зміст                                                                                                        |
| ------------ | ------------------------------------------------------------------------------------------------------------ |
| `src/core/`  | `ProcessMemory`, `Scanner`, `AddressTable`, `Freezer`, `DumpBook`, формули, структури, вказівники, емулятори |
| `src/ui/`    | `MainWindow`, діалоги, `ScanWorker` (пошук у `QThread`)                                                      |
| `tests/`     | `test_core.cpp` — сценарії без Qt                                                                            |
| `cmake/`     | номер збірки (`build_number`), `gamex_build_info.hpp.in`                                                     |
| `resources/` | іконки (qrc)                                                                                                 |
| `data/`      | `.desktop`, PNG/SVG для install                                                                              |

**Потік даних (типовий):** attach → `Scanner::scan` / `refine` (worker) → верхній список збігів → «Додати» → `AddressTable` → `Freezer::tick` / запис значення → опційно `.gxt`.

**Важливо для потоків:** під час `scanning_` UI **не** повинен чіпати `Scanner` (M1–M4, формула, undo тощо вже блокуються). Новий код, що читає hits під час worker — data race.

## Збірка

```bash
sudo apt install g++ cmake ninja-build qt6-base-dev
# опційно: libcapstone-dev  libx11-dev

cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
# або: ./build/gamex_core_tests
./build/gamex
```

Корисні опції cmake:

| Опція               | Значення                                       |
| ------------------- | ---------------------------------------------- |
| `GAMEX_BUILD_UI`    | `ON`/`OFF` — зібрати Qt-інтерфейс              |
| `GAMEX_BUILD_TESTS` | `ON`/`OFF` — тести ядра                        |
| `GAMEX_QT_ROOT`     | шлях до Qt з офіційного інсталера (`…/gcc_64`) |

Після кожної збірки `gamex` інкрементується `cmake/build_number` (файл у `.gitignore`) — версія вигляду `0.1.N`.

`compile_commands.json` з’являється в `build/` (`CMAKE_EXPORT_COMPILE_COMMANDS`); для clangd можна зробити symlink у корінь.

## Тести

- Усі зміни в `src/core/` — за можливості покрийте або розширьте `tests/test_core.cpp`.
- Watchpoint / ptrace тести чутливі до `kernel.yama.ptrace_scope` і sandbox; у CI або обмеженому середовищі частина може потребувати `ptrace_scope=0` або запуску поза sandbox.
- UI-тестів Qt немає — перевіряйте вручну сценарій attach → шукати → відсіяти → таблиця → `.gxt`.

```bash
cmake --build build --target gamex_core_tests
ctest --test-dir build --output-on-failure
```

## Стиль коду

- **C++20**, `-Wall -Wextra -Wpedantic` (core також `-Wshadow -Wconversion`).
- Namespace `gamex`. Заголовки поруч із `.cpp` (`foo.hpp` / `foo.cpp`).
- Рядки UI й довідки — **українською**; ідентифікатори / коментарі в коді — українською або англійською, узгоджено з сусіднім файлом.
- Не підключайте Qt у `src/core/`.
- Не ломайте сесію пошуку: після першого успішного scan тип/endian фіксовані до «Скинути пошук».
- Нові тексти користувача — оновіть **і** README / F1 (`src/ui/help_dialog.cpp`), якщо змінюється поведінка.

## Процес внеску

1. Форк / гілка від актуальної `main`.
2. Одна логічна зміна на коміт (або невелика серія); повідомлення — навіщо, не лише «що».
3. `ninja` + `ctest` локально перед PR.
4. У описі PR: що змінилось, як перевірити, чи чіпали межі продукту.

Питання щодо архітектури краще коротко описати в issue/PR до великого рефакторингу.

## Безпека

Повідомлення про вразливості в локальному доступі до пам’яті (наприклад обхід PID+starttime) — бажано приватно власнику репозиторію, не публічний PoC для чужих онлайн-ігор.
